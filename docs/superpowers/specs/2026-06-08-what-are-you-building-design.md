# What Are You Building — 设计文档

**日期**：2026-06-08
**状态**：已确认，待写实现计划

## 背景与目标

面向 vibe coder 的作品展示站。用户登录后发布自己在 build 的产品（名字 / 配图 / 简介），其他人点赞，按"最新 / 最火"流动排序。

**主要目标不是验证产品或技术**（作者清楚技术上很简单），而是**练习市场推广 / go-to-market**——把一个东西真正推向市场、并量化每个渠道的效果。因此本设计在两处刻意做重：

1. **产品自带传播引擎**（分享卡片），让 builder 为自己拉赞而主动分享，替作者完成一部分营销。
2. **完整埋点漏斗**，让作者能看见每次外推的真实转化，形成可优化的反馈回路。

产品定位为轻量个人小项目，不追求做成正式产品。

## 关键决策（已确认）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 登录门槛 | 发布和点赞都需登录，**仅 Google / GitHub OAuth** | 天然筛掉非开发者，早期社区浓度高、点赞可信、防刷票 |
| 传播驱动 | 第一步做「专属页 + 分享卡片」，徽章/榜单留第二步 | 最经典有效的裂变引擎，且能让作者看清分享→访问→转化链路 |
| 视觉风格 | **Editorial 黑白杂志风**（衬线大标题 + 等宽字点缀 + 硬边框） | 刻意去 AI 味；对设计者群体，审美就是第一道营销 |
| 首页布局 | **杂志混排**：置顶「今日头条 Top」+ 紧凑排行列表 | 最有杂志气质，自带「上头条」荣誉感，呼应第二步榜单玩法 |
| 分享卡片 | **杂志封面式分栏**（左文右图硬边框，名字当大标题） | 不依赖 builder 配图质量，靠排版就体面，整站调性统一 |
| HOT 排序 | **时间衰减热度**（赞数 ÷ 时间幂，HN/Reddit 式） | 新品冲得上、老品自然下沉，榜单持续流动，经得起天天看 |

## 范围

### 第一步 MVP（本设计覆盖）

核心循环：登录 → 发布 → 浏览 → 点赞 → 分享。

- **登录**：仅 Google / GitHub OAuth。
- **发布**：填表单入库，立即出现在 NEW 流。
- **浏览**：两个流——HOT（时间衰减热度）/ NEW（按创建时间倒序）。
- **点赞**：登录后才能点赞；每人每产品一票，可取消。
- **产品详情页**：独立 URL，**服务端渲染**（抓取器需读到 OG 标签），动态生成封面式分享卡片 PNG（带实时赞数 / 排名）。
- **埋点**：PostHog 打通推广漏斗。

### 明确不做（YAGNI，留给第二步）

评论、关注 / 个人主页、今日 / 本周榜单徽章、通知、搜索。等核心循环跑起来再加。

## 数据模型

极简两张表，用户身份复用 InsForge Auth，不单独建用户表。

### `products`
- `id`
- `name` — 产品名
- `tagline` — 一句话简介（≤60 字）
- `image_url` — 配图（存于 Storage）
- `link` — 产品链接（选填）
- `description` — 详细说明 markdown（选填）
- `author_id` — 关联 Auth 用户
- `vote_count` — 赞数缓存（便于排序，随投票更新）
- `created_at`

### `votes`
- `user_id`
- `product_id`
- `created_at`
- **唯一约束** `(user_id, product_id)` —— 防重复投票

### RLS 要点
- `products`：任何人可读；仅登录用户可插入，且 `author_id` 必须等于自身。
- `votes`：仅登录用户可对自己插入 / 删除一票；唯一约束在数据库层兜底防刷。
- `vote_count` 通过触发器或函数随 `votes` 增删维护，避免客户端可篡改。

## 架构与技术栈

基于 InsForge。

### 后端 — InsForge
- **Auth**：Google / GitHub OAuth。
- **Postgres**：上述两表 + RLS + 维护 `vote_count` 的触发器 / 函数。
- **Storage**：存产品配图（公开读）。
- **Posthog Integrate**：使用 Posthog 进行转化追踪

### 前端 — Next.js（App Router）
选 Next.js 而非纯 SPA 的硬原因：**产品详情页必须 SSR**——X / 微信等抓取器不执行 JS，只有服务端把 `og:image` / `og:title` 等 meta 直出，分享卡片才会显示。这是裂变引擎能否成立的前提。

### 分享卡片 — 动态 OG
用 Next.js 动态 OG（Satori：把「杂志封面式」HTML 渲成 PNG），按产品实时数据（名 / 图 / 赞数 / 排名）生成，URL 形如 `/og/[productId]`，被详情页 `og:image` 引用。

> 部署细节（InsForge 前端托管是否承载 Next.js SSR，或 OG 生成放 InsForge 边缘函数 vs. Next 路由）在实现计划阶段确认。

## 埋点 / 推广量化（核心目标）

用 **PostHog** 打通漏斗（InsForge 自带了 Posthog integration）：

```
分享链接点击 → 落地产品页 → 浏览首页 → OAuth 注册 → 点赞 / 发布
   (曝光)        (UTM 来源)    (留存)      (转化)      (激活)
```

- 每个外推渠道带 **UTM 参数**，对比「X vs Reddit vs 微信群」等渠道真正带来多少 builder。
- 关键事件：`product_page_viewed`、`signup_completed`、`product_submitted`、`vote_cast`、`share_clicked`。
- 这条反馈回路就是作者练推广的主要价值所在——让"把东西推出去"变得可测量、可优化。
